# Code of Conduct

## Our standard

Treat other contributors with respect. Assume good faith, give specific
technical feedback, and keep disagreement about the work.

Examples of acceptable behavior:

- Asking for clarification before rejecting an idea.
- Explaining a bug with a reproduction.
- Accepting that a maintainer may decline a change for scope or maintenance
  reasons.

Examples of unacceptable behavior:

- Harassment, threats, or personal attacks.
- Discriminatory language or imagery.
- Publishing another person's private information.
- Deliberately derailing an issue or pull request.
- Sharing secrets, session data, or private workspace paths without consent.

## Scope

This standard applies in repository issues, pull requests, discussions, and
other project spaces. It also applies when you represent the project in public.

## Enforcement

Report a problem to the maintainer through the GitHub profile. Reports are
handled privately. The maintainer may remove content, close a thread, or block a
participant. A response will explain the decision when it is safe to do so.

## Attribution

This is a short project policy, not a copy of a larger template.
